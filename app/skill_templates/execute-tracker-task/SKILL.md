# Выполнение задачи по номеру в трекере

Прочитай `AGENTS.md` и `docs/agents/workflow.md`, если он есть, от корня текущего
checkout. Выбери style guide по изменяемому коду: `docs/agents/style-guide.md`
для Python, `docs/agents/frontend-style-guide.md` для frontend, оба для смешанной
задачи. Применяй выбранные документы при реализации и ревью,
включая размеры кода, форматирование и слои. Если его нет, явно сообщи об отсутствии
и используй существующие правила проекта; не выдумывай стандарт.
Определи репозиторий, ветку и полный SHA через Git. Не считай номер задачи
глобально уникальным и не подставляй номер вместо внешнего ID или локального task_id.

Для Shared Access вызови list_projects и выбери проект, в разрешённых репозиториях
которого есть текущий репозиторий. Найди задачу через list_tracker_tasks, следуя
next_cursor до нахождения однозначного совпадения или исчерпания страниц. Сопоставляй
полный identifier/ключ или документированный номер в пределах выбранного проекта,
либо точный внешний ID. Если провайдер не отдаёт номер, используй доступный поиск
трекера для подтверждения соответствия или запроси внешний ID/ссылку. Не угадывай
задачу по похожему названию и не создавай новую вместо ненайденной.

При нескольких подходящих проектах или совпадениях запроси недостающий ключ проекта.
При недоступном трекере сообщи об ограничении; не заявляй кэшированные требования
актуальными. Не обходи проверку доступа и не запрашивай секреты в тексте чата.

Зарегистрируй найденный внешний ID через register_task и сохрани возвращённый task_id.
Вызови get_task_context с текущим репозиторием и точным SHA, проверь свежесть,
предупреждения, недавние отчёты и рабочие сессии. Прочитай необходимые полные документы
через read_project_document и локальные спецификации; при отсутствии документов
этой ревизии не подменяй её main. Начни start_work_session с реальными веткой и base_sha.
Личность разработчика определяет аутентификация, не параметры агента.

Сформулируй критерии приёмки из требований задачи и реализуй её по локальной архитектуре
и testing.md. Для подробного порядка реализации используй соседний навык
`../implement-specification/SKILL.md`; для Python unit-тестов при необходимости —
`../python-unit-tests/SKILL.md`. Не расширяй объём до соседних задач. Если требования
конфликтуют или задача уже выполнена, проверь факты и опиши ситуацию до дублирования работы.

Перед завершением проверь изменённый код по выбранному guide: лимиты 500 SLOC/50 строк,
formatter соответствующего стека либо документированное исключение, объекты,
интерфейсы, mapping и ответственность сервисов. Для UI проверь также состояние,
доступность и оптимизацию. Укажи нарушения и пропущенные проверки;
не объявляй соответствие по одному чтению документа.
Выполни обязательные проверки и подготовь отчёт по `docs/agents/report.md`, используя
`../work-report/SKILL.md`. Публикация отчёта допустима в рамках разрешённого workflow
проекта; сохраняй ключ идентичного повтора и явно указывай пропущенные проверки.
Сообщи найденные ключ/ID, результат, состояние изменений и оставшиеся действия.
Не переводи задачу в done автоматически: отчёт и переход статуса — разные операции.
