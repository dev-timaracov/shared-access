## Причина и исправление

Plane возвращает `next_cursor` даже у последней пустой страницы с `next_page_results=false`. Адаптер игнорировал этот признак и выполнял лишние GET до 429, не публикуя отчёт. Теперь он проверяет совпадение отчёта на текущей странице, затем останавливает поиск при `next_page_results=false`. Для ответов без этого поля сохранена прежняя обработка курсора.

Добавлены восемь регрессионных случаев для v1/v2: пустая и непустая последняя страница с курсором; следующая страница с существующим отчётом или без него. Проверяются число запросов, отсутствие лишних страниц, отсутствие дублей и экранирование HTML.

Также fixtures явно включают авторизацию, чтобы `AUTH_DISABLED=true` из локального `.env` не менял идентичность и поведение тестов. Настройки рабочего сервиса не изменены.
