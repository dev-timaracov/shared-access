## Найденные проблемы

1. Тестовые fixtures наследуют `AUTH_DISABLED=true` из локального `.env`, поэтому четыре проверки авторизации ошибочно работают как local-admin. Повтор с `AUTH_DISABLED=false` подтверждает корректную авторизацию; fixtures следует изолировать от локального режима.
2. Реальная публикация отчёта через worker не прошла: `publish_report` следует за непустым `next_cursor` даже на пустой конечной странице Plane с `next_page_results=false`. Было 55 GET-запросов, последний вернул 429. Отчёт `192c5e5c-8486-4af9-9e81-353c6b2d393e` сохранён; доставка не состоялась. Проверка реальной дедупликации публикации из-за этого не завершена.

Тестовое задание outbox `e16b4dd8-0ef5-442a-a2fa-c450dbb2f386` после первой неудачи остановлено администратором переводом в dead, чтобы не повторять поток запросов. Отчёт и запись задания сохранены. Существующая настройка синхронизации сервера осталась отключённой; только одноразовое REST-приложение включало её для этого отчёта.
